믿을 수 있는 사람인지 먼저 보이게

출시 전에 브리더와 샵에 직접 연락해 이야기를 들었습니다. 가장 많이 나온 걱정은 상대를 믿어도 되느냐였습니다. 그래서 글마다 올린 사람과 거래 완료 수를 보여 주고, 거래 후기는 실제 입양자만 쓰게 했습니다.

상품이 아니라 분양

동물을 상품이라고 부르는 게 싫다는 말을 들었습니다. 화면의 말은 모두 분양글, 분양중, 입양자로 바꿨습니다. DB와 API 값은 그대로 두고, 화면에 보일 때만 바꾸는 함수 하나를 웹과 앱이 같이 씁니다.

2
브리디

화면 뒤도 직접 짰습니다.

Next.js API와 Prisma, PostgreSQL로 회원, 분양, 경매, 채팅, 알림을 만들었습니다. 앱은 Expo로 만들고 웹과 같은 규칙 코드를 나눠 씁니다.

유찰된 경매는 다음 회차로

유찰된 경매를 새 글로 다시 올리면 조회와 관심 기록이 사라집니다. 같은 경매에 회차를 붙여 다시 열고 지난 입찰은 따로 보관합니다. 연락이 끊긴 낙찰자는 다음 회차에 입찰할 수 없습니다.

필요한 부분만 새로 그리는 캐시

상세 페이지는 ISR로 미리 만들어 두고, 글을 고치면 그 페이지만 다시 만듭니다. 좋아요나 경매 현재가처럼 자주 바뀌는 숫자는 브라우저에서 따로 그립니다. 목록 API는 CDN 캐시로 DB 호출을 줄였습니다.

다시 오게 만드는 알림

동네 무료 분양, 토론 마감, 관심 분야 새 글, 답이 없는 질문을 서버에서 보냅니다. 한 사람이 하루에 받는 횟수와 밤 시간 발송은 서버에서 막습니다. 웹은 Web Push, 앱은 FCM입니다.

가볍고 덜 흔들리게

안드로이드 앱은 R8을 켜서 DEX를 62.5MB에서 25.0MB로 줄였습니다. 홈의 하이드레이션 오류는 서버와 브라우저 HTML을 맞춰 하루 52건에서 11건이 됐습니다.

4
Cue

계약서 일을 덜어 주는
AI 계약 앱.

BHSN에서 Cue의 프론트엔드를 맡고 있습니다. SvelteKit 앱 안에 React로 만든 에이전트 화면을 마이크로 프론트엔드로 띄웁니다.

one.allibee.ai

두 제품의 가입을 하나로

앨리비와 Cue는 가입이 따로였고, 돌아오면 토큰이 만료되거나 워크스페이스가 두 개 생겼습니다. 백엔드와 상의해 서버끼리 로그인을 처리하게 바꿨습니다. 프론트는 이제 한 곳만 봅니다.

계약서 두 개 비교

삼성SDS 요구로 시작했습니다. 형식이 다른 두 계약서를 OCR로 읽고 diff-match-patch로 차이를 찾아, 수정과 삭제와 추가를 표시합니다. 7주 만에 기본 기능이 됐습니다.

광고가 가입으로 이어지는지

가입 API에 유입값이 한 번도 넘어가지 않고 있었습니다. 주소에 유입값을 실어 가입까지 이어 가게 했고, 유입 채널이 보이는 가입이 0%에서 79%가 됐습니다.

문서 저장소

목록을 서버 정렬과 커서 기반 무한 스크롤로 다시 만들고 검색을 서버로 옮겼습니다. 검색어 강조는 텍스트 노드로 그려 XSS를 막았습니다.

휴대폰에서 쓰는 에이전트

대화, 내역, 캔버스를 모바일용으로 다시 짰습니다. 바텀시트는 내용 영역을 끌어도 닫히고, CDP로 실제 터치를 보내는 테스트로 확인합니다.

6

이렇게 만듭니다.

프로젝트마다 직접 설정하고 운영해 본 것들입니다.

배포

웹은 브랜치마다 Vercel 프리뷰가 뜨고, 운영 릴리스 PR은 CI 품질 검사를 통과해야 머지됩니다. 데이터를 덮어쓰는 마이그레이션은 CI가 빌드를 멈춥니다. 앱은 JS만 바뀌면 EAS Update로 바로 내고, 네이티브가 바뀌면 fingerprint로 알아채 스토어 빌드를 만듭니다. 스토어 제출과 출시 노트도 API로 합니다.

캐싱과 Vercel

ISR과 on-demand revalidate로 바뀐 페이지만 다시 만듭니다. 목록 API는 s-maxage와 stale-while-revalidate로 CDN에 둡니다. 알림 발송은 Vercel Cron으로 돌리고, 환경변수는 프리뷰와 운영을 나눠 둡니다.

테스트

Playwright로 로그인, 채팅 보내기와 읽음, 관심 등록 흐름을 브라우저에서 확인합니다. 모바일 바텀시트는 CDP로 실제 터치를 보내 끌어서 닫히는지 봅니다. 웹과 앱이 같이 쓰는 규칙 코드는 같은 Jest 케이스로 양쪽을 검사하고, 화면이 바뀐 PR에는 캡처가 자동으로 붙습니다.

서버 상태

앱은 TanStack Query, 웹은 SWR을 씁니다. 관심 분야를 쿼리 키에 넣어 목록 캐시를 나누고, 채팅과 댓글은 낙관적 업데이트로 보내자마자 보입니다. 워크스페이스를 바꾼 뒤 늦게 도착한 응답은 버립니다.

다국어

Cue는 구글 시트에서 번역 파일까지 자동으로 이어지고, 언니노트는 9개 언어를 언어별 주소로 냅니다. 브리디 앱은 i18next로 나라와 언어를 나눠 둘 준비를 마쳤습니다.

웹뷰와 복잡한 화면

웹뷰 하이브리드 앱을 만들고 postMessage로 웹과 네이티브가 주고받게 했습니다. 컬럼 너비를 끌어서 바꾸는 테이블처럼 손이 많이 가는 관리 화면도 만듭니다. 반복되는 배포와 PR 정리는 스크립트로 만들어 공개해 두었습니다.
