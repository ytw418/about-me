W1

Cue 문서 저장소와 업로드를 다시 설계하기

상태 설계목록 · 검색
문제

계약이 체결 전 · 체결 완료 두 단계로 나뉘었는데 두 화면이 같은 폴더 트리를 봐서, 폴더 생성 · 업로드가 엉뚱한 곳에 들어가거나 오류가 났습니다. 검색은 이미 불러온 항목 이름만 걸렀고, 업로드 패널은 새로고침하면 항목이 두 번 보이거나 사라졌습니다.

해결
  • 서버 정렬 · 커서 기반 무한 스크롤 · URL 검색어 동기화(300ms 디바운스) 목록을 새로 만들었습니다.
  • 폴더 요청 캐시와 업로드 경로 키를 단계별(stage:folderId)로 나눴습니다.
  • 검색을 서버 검색 API로 바꾸고 관련도 순서를 유지했습니다. 하이라이트는 {@html} 대신 텍스트 노드로 그려 XSS를 없앴습니다.
  • 업로드 패널은 버전을 붙인 sessionStorage 스냅샷으로 복원하고, 워크스페이스를 바꾼 뒤 늦게 온 응답은 버립니다.

목록 · 검색 · 업로드문서 저장소 흐름을 맡아 다시 짬

W2

두 제품의 회원가입 · 로그인을 하나로

인증 · SSO가입 전환
문제

앨리비와 Cue의 가입 · 약관이 따로였고, 가입하고 돌아오면 일회용 토큰이 만료되거나 워크스페이스가 두 번 만들어졌습니다. 구글 SSO 첫 로그인 때는 '생성 중' 화면이 건너뛰어졌습니다.

해결
  • 앨리비 가입을 Cue 가입으로 모으고, 가입 응답의 일회용 토큰으로 앨리비에 바로 로그인시켰습니다.
  • 약관을 서비스:ID 복합키로 구분해 한 번에 받고, 로그인 뒤 재동의 모달을 없앴습니다.
  • 워크스페이스가 반영될 때까지 0.5초 간격 최대 12번 다시 조회해 중복 생성을 막았습니다.
  • SSO 콜백에서 하던 생성을 환영 화면으로 옮겨 로딩 화면을 되살렸습니다.
  • 광고 유입 첫 · 마지막 UTM을 가입 API로 보내 가입 전환을 측정하게 했습니다.

고객 한 곳의 요구가 제품 기능이 된 계약서 비교

문서 뷰어diff
문제

초안과 체결본, 형식이 다른 계약서를 비교할 방법이 없었습니다. OCR 분석이 최대 5분까지 걸려 타임아웃이 잦았습니다.

해결
  • 기존 OCR 뷰어 위에 비교 뷰와 전체 화면 비교 모달을 올리고 diff-match-patch로 차이를 계산했습니다.
  • 처음 복사해 만든 뷰어를 래퍼 구조로 리팩터링했습니다(−458줄).
  • 5분 상한에 맞춘 로딩 · 중단 버튼, 공백만 바뀐 변경 표시, 겹치는 변경 태그 자동 오프셋, 닫힌 패널의 태그를 누르면 열고 스크롤하기를 넣었습니다.
  • 라이트 버전 제품까지 같은 기능을 넓혔습니다.

D1미니홈피는 안 만들었습니다

  • 브리디의 한 방이 뭘까 고민하면서 미니홈피 꾸미기, 소개팅, 동네, 기록을 후보로 놓고 실제 글과 방문 기록을 뒤졌습니다. 꾸미기나 소개팅을 원하는 글은 한 건도 없었습니다.
  • 그래서 손으로 쓰는 기록보다 거래하면 저절로 쌓이는 기록(낙찰, 거래 이행, 체장)이 사람을 붙잡을 거라고 보고 그쪽으로 좁혔습니다.

D2당근이 막은 손님 받기

  • 당근에서는 생물 분양 글을 못 씁니다. 갈 데가 없어진 물고기·곤충 동네 나눔은 바로 받아서 홍보했습니다.
  • 릴레이 임보나 캣맘 모임은 받지 않기로 했습니다. 당근이 그걸 막은 이유(맡기고 잠적하는 일)까지 같이 떠안게 되니까요. 햄스터나 토끼 분양이 몰리면 영업 신고 문제가 생길 수 있다는 것도 미리 짚어 뒀습니다.

D3'상품'이라는 말을 뺐습니다

  • '상품', '판매'라고 하면 동물이 물건처럼 보여서 화면 문구를 전부 '분양', '입양'으로 바꿨습니다. DB 값은 그대로 두고 화면에 보여 줄 때만 바꿉니다.
  • 강아지·고양이 키우는 분들은 '브리더'라는 말에서 펫숍을 떠올립니다. 그래서 포유류만 고른 사람에게는 '집사'라고 부르고 경매도 숨깁니다. 파충류·곤충 쪽에서는 브리더가 자랑이라 그대로 뒀습니다.

D4텅 빈 게시판은 공공 데이터로

  • 강아지·고양이 탭을 열면서 분양보다 입양을 먼저 보여 주고 싶었습니다. 공공 유기동물 API로 보호소 공고 2,400건을 가져와 '보호소 아이들'에 넣었습니다.
  • 3시간마다 다시 맞추고, 두 번 연속 안 보이는 공고는 숨깁니다. 다만 한 번에 30% 넘게 사라지면 아이들이 입양 간 게 아니라 API가 고장 난 거라서 숨기지 않습니다.

D5모르는 사람한테 생물을 받으려면

  • 개인끼리 생물을 주고받을 때는 결국 '이 사람 믿어도 되나'가 전부입니다. 그래서 목록 카드마다 누가 올렸는지 보이게 하고, 프로필에 거래 완료 수와 활동 기간을 띄웁니다.
  • 거래 후기는 분양자가 입양자로 지정한 사람만 쓸 수 있습니다. 가짜 후기는 쓸 자리부터 없습니다.

D6해외는 아직이지만 자리는 깔아 뒀습니다

  • 해외 진출은 미뤘지만 DB에 country와 locale은 먼저 넣었습니다. 분양·경매는 나라마다 법이 달라서 나라로 나누고, 커뮤니티는 언어로 나눕니다.
  • 경매는 다시 열어도 새로 등록하지 않고 회차로 이어지고, 모든 목록은 카테고리 트리 하나로 거릅니다.
