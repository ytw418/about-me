01

혼자서 웹과 앱이 어긋나지 않게 만들기

아키텍처개발 프로세스
문제

웹을 앱 디자인에 맞춘 뒤에도 앱 전용 기능이 쌓이면서 다시 벌어졌습니다. 점검해 보니 앱 화면 56개 중 44개만 웹에 있었습니다.

해결
  • 앱 · 웹 모두 "항상 같이 바꾼다"를 기본으로 두고, 예외는 기기 기능(app-only)과 웹 전용(web-only) 두 가지로만 정했습니다.
  • 화면 코드 커밋에 Parity: both | app-only | web-only 트레일러가 없으면 훅이 막고, 한쪽만 고치고 끝난 작업은 되돌려 보냅니다(훅 테스트 42건).
  • 본문 포맷 · 알림 문구 같은 규칙 모듈은 웹 원본과 앱 사본을 같은 JSON 픽스처로 테스트합니다.
  • parity:audit 스크립트로 웹 · 앱 화면 경로를 대조해 빠진 화면을 찾습니다.
결과
78.6% → 100%웹 · 앱 화면 경로 일치 (56/56)
  • 하루 동안 PR 2개로 정리
  • 이후 화면 커밋마다 Parity 표시가 남음
02

AI 에이전트 사고를 규칙이 아닌 장치로 막기

안전DevOps
문제

코딩 에이전트가 Prisma migrate diff의 임시(shadow) DB 자리에 공유 dev DB 주소를 넣어 dev DB 데이터가 모두 지워졌습니다(운영 영향 없음). 백업도 없었습니다.

해결
  • 에이전트 단계: 터미널 · 파일 쓰기 · 외부 도구 호출을 모두 검사하는 DB 가드 훅. 초기화 · DROP · 실제 DB를 shadow로 쓰는 명령은 거부합니다(테스트 케이스 80여 건).
  • 빌드 · CI 단계: 데이터를 지우는 마이그레이션은 이유 표시가 없으면 빌드가 멈추고, PR마다 스키마와 마이그레이션 일치를 검사합니다.
  • 백업: 매일 읽기 전용 계정으로 덤프 → 복원 검사 → 암호화 보관(일간 35일 · 주간 90일).
결과
3중 방어사고 1시간 30분 안에 · 비용 0원
  • 복구 목표 RPO 24h · RTO 1h, 복원 연습 통과
  • 점검 중 "프리뷰 빌드가 dev DB에 마이그레이션을 바로 적용"하던 위험도 찾아 막음
03

DB를 바꾸지 않고 사진 · 글 블록 에디터 만들기

에디터호환성
문제

사진은 위쪽 썸네일 줄, 글은 아래라서 사진과 설명이 번갈아 나오는 사육기 · 세팅기를 쓸 수 없었습니다. 앱(RN)과 웹에서 똑같이 동작해야 했습니다.

해결
  • 라이브러리 에디터를 검토한 뒤 줄 단위 블록 에디터를 직접 만들었습니다.
  • 기존 텍스트 컬럼에 [[photo:N]] · ## · **굵게**만 넣는 형식을 정해 DB 변경 없이 저장합니다. 사용자가 친 같은 글자는 이스케이프합니다.
  • 표시가 없는 옛 글은 예전처럼 보이게 하고, 잘못된 사진 번호는 글자로 처리합니다.
  • 형식 모듈을 앱 · 웹이 같은 파일로 쓰고 같은 케이스로 테스트합니다.
결과
마이그레이션 0옛 글 그대로 호환
  • 에뮬레이터 E2E 통과 후 웹 운영 배포
  • Android 커서 튐 버그를 에뮬레이터에서 잡아 수정

04

경매가 끝난 뒤에도 다시 시작할 수 있게

데이터 모델링
문제

유찰되거나 낙찰자가 연락 없이 사라지면 같은 개체를 처음부터 새로 등록하는 수밖에 없었습니다.

해결
  • 새 행을 복사하지 않고 같은 경매의 회차(round + 1)로 다시 엽니다. 지난 회차 입찰은 archivedAt으로 보관합니다.
  • 노쇼한 이전 낙찰자는 차단 명단 테이블로 다음 회차 입찰을 막고, 다시 시작할 때는 기간만 바꿀 수 있게 했습니다.
  • 마이그레이션 안전 검사가 UPDATE backfill을 막아서, 기본값만으로 동작하게 설계했습니다.
결과
다음 회차로새 등록 없이 같은 경매를 다시 시작
  • 링크 · 이전 입찰 기록이 끊기지 않음
  • 웹 운영 배포, 앱에도 같은 기능 반영
05

알림이 사라지는 버그를 고치고 화면을 다시 짜기

버그 수정UX
문제

알림 화면에 들어가자마자 전체를 읽음으로 바꾸는 요청이 나가, 새 알림 표시가 확인하기도 전에 사라졌습니다. 목록도 글자만 있어 무엇에 대한 알림인지 알기 어려웠습니다.

해결
  • 진입 시 호출을 없애고, 누른 알림 하나와 '모두 읽음' 버튼만 읽음 처리합니다.
  • 오늘 · 최근 7일 · 이전으로 묶고, 사람 알림은 아바타 + 종류 뱃지, 시스템 알림은 아이콘으로 나눴습니다.
  • 서버 응답에 대상 사진을 추가해 오른쪽 썸네일로 보여 줍니다. 표시 규칙은 앱 · 웹 공유 모듈입니다.
결과
앱 · 웹 함께버그 수정 + 리디자인 배포
  • HTML 시안 → A안 선택 → PRD 수용 기준으로 검증
06

앱 크기와 지표 신뢰도 바로잡기

성능데이터
문제

Play 콘솔에서 코드 최적화 미달 경고를 받았고(R8 꺼짐), PostHog 지표는 페이지뷰 누락 · 사용자 식별 0건 · 오류 이벤트 소음 때문에 믿기 어려웠습니다.

해결
  • R8 축소 · 리소스 정리를 켜고 카카오 SDK 규칙을 넣은 뒤, 빌드 산출물을 직접 풀어 영역별로 크기를 쟀습니다.
  • 측정 결함 4개 수정: 앱 안 이동 페이지뷰 누락, identify 누락, 비로그인 401 소음, 섹션 노출이 로드 때 한꺼번에 찍히던 문제.
  • 서버 · 웹 · 앱 이벤트를 하나의 기준표로 관리하고, 가입 완료는 서버에서 기록합니다.
결과
DEX −60%62.5 → 25.0MB (arm64)
  • 다운로드 추정 41.6 → 29.0MB
  • 클래스 92% 난독화
  • 수정 배포 시각 기준으로 지표를 나눠 봄
